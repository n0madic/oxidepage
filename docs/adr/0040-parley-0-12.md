# ADR-0040: Move to parley 0.12, skipping 0.11

- Status: accepted
- Date: 2026-11-04

## Context

parley was pinned at `=0.10.0`. Dependabot proposed 0.11.1, and that version
makes 20 WPT files hang: `break_all_lines` spins forever on a
`CustomOutOfFlow` inline box, because `break_next` yields on it without
advancing (linebender/parley#752). Every float we build is a `CustomOutOfFlow`
box, which is why exactly the float-containing files hang. The fix
(linebender/parley#753) was announced as a 0.11.2 backport. That release was
never published. The fix ships in 0.12.0 (2026-10-09).

0.12.0 is a breaking release in ways that reach layout semantics, not only
signatures:

- `white-space-collapse` is now a per-span style, and
  `TreeBuilder::set_white_space_mode` is gone. parley also collapses
  whitespace *across* span and inline-box boundaries itself (pending
  whitespace is committed lazily), and it implements `PreserveBreaks` and
  `BreakSpaces`.
- Lines are sized by the CSS line-box model. `LineMetrics::{ascent, descent}`
  are gone; `content_block_{min,max}_coord` carry the typographic extent
  (inline boxes included, as 0.10's `ascent`/`descent` did).
- Spans and inline boxes carry a `VerticalAlign`, and `InlineBox` carries an
  optional baseline.
- `Cluster` spans a whole grapheme cluster, and `Run::metrics()` became
  `Run::font_metrics()`.

## Decision

We skip 0.11 entirely and pin `=0.12.0`.

- **Whitespace.** `layout::text::style` writes `white_space_collapse` into
  every span's `TextStyle`, so the IFC root's mode comes from its own style.
  `display: contents` has no span of its own, so it pushes a style-modification
  span that carries only its `white-space-collapse`. `<br>` pushes one carrying
  `Preserve`. All four CSS modes now map one-to-one; the old
  `PreserveBreaks`/`BreakSpaces` → `Preserve` approximation is gone.
  We dropped the empty push/pop span that 0.10 needed to stop
  `pop_style_span` from trimming an inline element's trailing space: 0.12
  defers that whitespace until it knows what follows.
- **`vertical-align` is mapped.** `layout::text::vertical_align` converts
  stylo's `alignment-baseline` and `baseline-shift` longhands to parley's
  `VerticalAlign`, for text spans and atomic inline boxes alike. A length or
  percentage shift resolves against the element's own line-height. The IFC
  root's own value is reset to `baseline`, because it places the root in its
  *outer* line and must not shift the root's content. css-inline-3's
  `baseline-shift: center` has no parley counterpart and stays on the
  baseline. This is not optional with 0.12: under the line-box model, a
  baseline-aligned inline-block also picks up the strut's descent. Without
  the mapping, `vertical-align: top` content (e.g.
  `css-flexbox/percentage-size-quirks-002.html`) regresses.
- **Geometry.** `getClientRects` fragments and the IFC hit test use
  `content_block_{min,max}_coord` where they used
  `baseline ∓ ascent/descent`.
- **Inline boxes** still report `baseline: None`: an atomic inline sits on its
  bottom margin edge, as before. An inline-block's own last-line baseline is
  a separate change, not part of this migration.

## Consequences

- With the same corpus, WPT goes from 18602 to 18615 of 24661 subtests passing.
  13 expectations are removed and none added, with no HANG or CRASH. The new
  passes are `elementFromPoint`/`elementsFromPoint` hit testing,
  `getClientRects-inline-inline-child`, and `scrollIntoView` on elements
  positioned by `vertical-align`. Goldens, reftests, Puppeteer and
  Playwright are unchanged.
- One unit expectation moved for the better:
  `XX<inline-block 30px>XX` in Ahem 10px/10px now gives a 32px line, not
  30px (30px above the baseline plus the strut's 2px descent), which is how
  browsers lay it out.
- The lockfile still carries two skrifa stacks (parley's 0.44 and our 0.46),
  now one minor version apart instead of four.
- Every Dependabot proposal for parley is a migration to be checked against
  the full gate in the `Cargo.toml` pin comment, never a lockfile-only merge.
